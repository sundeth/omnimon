Version 1.0.0 Beta 2 July 4, 2026
Download release
Beta 2 focuses on the Android experience, the new Digimon Database sprite service, and a large round of interface polish. The Android background service now ships and keeps pets progressing while the app is in the background, the sprite library was reorganized and expanded, and the shop, Digidex, and main game scenes received many usability fixes.

Android

  • New Background service. The background service announced in Beta 1 now ships. When the app is minimized or closed, a foreground service keeps ticking every active pet once per minute, saves progress periodically, and sends notifications when a pet gets sick, poops, calls for attention, or starts dying. The service reports its own status through notifications (started, running, idle, or the error it hit), and the settings menu shows its state.
  • Fixed Black screen on resume. Switching to another app and back no longer leaves the game on a black screen. The display is re-acquired only after Android has rebuilt the window, with verification and retries, and the game self-heals if a frame fails to present.
  • Fixed Live render resolution. Changing the Render Res setting now takes effect immediately instead of drawing in a corner of the screen until the next restart.
  • New Shake detection. Shake-based interactions (training, saving a dying pet) now work on Android using the phone's accelerometer, matching the Raspberry Pi hardware behavior.
  • Fixed Battery indicator. The clock bar now shows the phone's real battery level and charging state instead of a permanently empty icon.
  • Fixed Attack speed on wide screens. Training and battle attack sprites now cross the screen in the same time on every resolution; on phones they previously crawled across the wide display.

Digimon Database and Sprites

  • New Digimon Database. A new online sprite service is live. The game checks it once per day at boot and refreshes the sprites of installed modules automatically; freshly downloaded modules fetch their sprites right after install.
  • Improved Sprite library reorganization. The bundled sprite library was renamed to a consistent naming standard (for example "Agumon X" is now "Agumon (X Antibody)") and expanded with hundreds of new and updated monster sprite archives.

Accounts and Modules

  • New Owned module sync. Modules purchased on an account are now synchronized: missing modules can be re-downloaded automatically when logging in on a new device.
  • Improved Login flow. The login scene was reworked, and text fields no longer type a stray character when clicked. Display settings are preserved when switching between accounts and game modes.

Shop

  • Improved Download feedback. Download progress, errors, and completion are now shown on a colored status line ("Downloading 42%", "Error, try again", "Installed"/"Owned") instead of inside the disabled button, and failed downloads can be retried immediately.
  • Improved Free Mode labels. Free Mode shows a green "Installed" badge for modules already on the device instead of the meaningless "Owned" flag.
  • Improved Module details. The description panel is much taller and slowly auto-scrolls when the text doesn't fit. Long descriptions are finally readable.
  • Fixed List rendering. Shop list items now draw their full right border.

Interface and Gameplay

  • New Pet selection by touch and mouse. Tapping or clicking a pet now selects/deselects it, exactly like the keyboard and joystick flow. In mouse mode, hovering a pet shows a yellow outline. Clicking empty space still toggles the hearts view.
  • Improved Pet placement on wide screens. Pets are distributed around the center of the screen instead of being pushed out to the corners on wide displays.
  • Fixed Digidex. Pet sprites now load correctly in the list and evolution tree, the name and stage labels use a readable size, the "Known" filter applies immediately, and Reset asks for confirmation.
  • Improved Pixel-perfect text. All text renders without anti-aliasing at the fonts' native pixel grid, keeping the interface sharp at every resolution. Input fields, the mode selection description, and several other components were snapped to the grid.
  • Improved Sharp sprite scaling. The status screen pet list and carousel icons use nearest-neighbor scaling, removing the blurry edges.
  • Fixed Feeding animation. Food sprites render at half their previous size, no longer covering the pet.
  • Improved Settings rows. Option rows respond to clicks on their < and > zones and show a muted style when disabled.

Module Editor

  • New Collection tab (Stage 1). Modules can now define a collection of collectable cards (Soul Plate, DDP Chip, iD Plate, or custom) with cards, effects, and card packs. Includes ZIP import, artwork editing through the Digimon Database card maker, RFID payload export for physical cards, and generated collection documentation. The in-game and server sides of the Collection system are planned for a later release.
  • New Digimon Database integration. Pets can be added to modules directly from the Digimon Database, sprites can be updated from it, and content reports can be generated against it.
  • Improved Omninet publishing. Login and module publishing against the Omninet server were refined, alongside various tab fixes.

Omninet

  • Improved Reward endpoints. The server's reward endpoints were updated.
Beta notes. The Android background service is new and still has a few known issues; if it misbehaves, its status notifications and the settings menu indicator will say why. The Arena remains planned but not yet playable.
Version 1.0.0 Beta 1 June 4, 2026
Download release
This is the first beta of the 1.0 release. It introduces the Omninet online services, an in-game shop, account-linked save files, a first-run setup wizard, an in-game tutorial, dot sprite support, and significant module accuracy work. The Arena mode is designed but not implemented in this beta and is planned for a later update.

Setup and Game Modes

  • New First-run setup wizard. On first boot the game walks the user through input remapping (joystick, keyboard, GPIO), a graphics performance test that determines a stable resolution, and the selection of a game mode. All settings can be changed later from the options menu.
  • New Progress Mode. Requires an Omninet account and an internet connection. Modules beyond the first are purchased with in-game Coins. Grants access to the shop's premium items and, in a future update, the Arena.
  • New Free Mode. Requires no account or internet connection. The shop is limited to free module downloads and the Arena is unavailable. Intended to keep the game fully playable if the online services are eventually retired.
  • Improved Mode switching. The user may switch between Progress Mode and Free Mode at any time. Save files are tied to the account, so each account maintains independent progress. Free Mode uses a single shared account with its own save data.

Omninet and Shop

  • New Omninet server. The online backend is now operational. It handles account management, module distribution, and shop transactions. The server is open source at github.com/sundeth/omninet.
  • New In-game module shop. Modules can be browsed and purchased directly from the game. Official modules cost 50 Coins; mini-games cost 20. Manual installation remains supported.
  • New Shop cosmetics and items. Backgrounds, items, and gameplay features are also available for purchase. A small set of premium items requires longer playtime to acquire.
  • New Coin economy. Coins are awarded for discovering secrets, evolving a pet, evolving a pet for the first time, completing Adventure Mode areas, and placing in the top three of an Arena season. The game has no real-money transactions.
  • New Starter reward. Completing the tutorial grants 50 Coins and opens the shop so the player can purchase their first module.

Tutorial

  • New In-game tutorial. An introductory tutorial covers the core gameplay loop of feeding, training, and battling. It ends with the starter Coin reward and a shop visit.

Sprites

  • New Dot sprite support. The game now distinguishes between three sprite types: dot (classic monochrome sprites), color (the existing default), and HD (Vital Bracelet sprites). Classic modules may continue to be played with color sprites.
  • New Dot sprite library. Over 7,000 dot frames have been prepared, covering pets, attacks, and care animations for DM20, PEN20, DMX, and PENZ modules.
  • Note Sources. Color sprites are sourced from the community DMC Sprite Database. Dot sprites required extensive manual preparation as no equivalent repository was available.

Pet and Game Systems

  • New Pet index value. Each pet has an index used for sorting and for exchanging data with real devices.
  • New DMX and PENZ critical attacks. Critical attack sprites have been mapped and colored. Further in-game refinement is planned.
  • Improved Pet timer rework. The timer system now runs consistently regardless of frame rate and more closely matches real device behavior.
  • Improved Animation skipping. Most animations may now be skipped.
  • Improved Multiple save files. Save files are tied to accounts. Multiple accounts may exist with independent progress.

Battle Accuracy

  • Improved DM20. Single battles now match real DM20 hardware. Attack patterns were mapped manually by running several DM20 units in parallel with Omnipet.
  • Improved PEN20. Battle patterns have been mapped. Verification on real hardware is pending.
  • In progress DMX and PENZ. Battle accuracy work for these devices is ongoing.

Module Editor

  • Improved Tab reorganization. The Main tab has been split into Main, Battle & Training, Care & Death, and Misc.
  • New Dot sprite support. The editor can now manage dot sprites for classic-style modules.
  • New OEM protocol field. When two devices share an OEM protocol, the game transmits the device version and index, which enables unlocks on real physical devices during battles.
  • New Adventure battle style. Three styles are now selectable: Area Selection (existing default), Next/Reset (DM20 behavior), and Random.
  • New Battle cost. Modules may use DP (DM20), Hunger (DMX), or None (DMGZ) as a battle cost.
  • New Battle feeding. A mid-progression feeding mechanic for sequential battles, modeled on DMX.
  • New Disable evolution counters while sleeping. Flag that stops evolution counters during sleep, as on the DM20.
  • New Can Eat Sleeping. When enabled, feeding actions are blocked while the pet is asleep.
  • New Care 99g effect. Configurable effect for the 99g care mistake: Skull (DM20), Dots (DMX), or None.
  • New Poop alarm toggle. The poop alarm may be enabled or disabled per module.
  • New Care poop sickness. The number of poops required for sickness is configurable. The formula is (number of pets - 1) × care_poop_sickness_count, so two DM20 pets become sick after four poops.
  • New Care poop sickness effect. The sickness effect may be set to Skull, Dots, or disabled.
  • New Activity restriction flags. New flags disable battles while sick and disable any action while sleeping or asleep.
  • Improved Save by shake / B press. The save mechanic for Pendulum and DMX-style devices is now closer to real hardware. In touch and mouse modes, clicking the dying pet is registered as a B press.
  • New Pet search. Pets may now be searched by name within the editor.
  • New Report feature. Users may report issues with modules from within the editor.
  • New Omninet connectivity. The editor can log in and publish modules directly to the Omninet server. The Module Editor now has its own repository at github.com/sundeth/Omnipet-Module-Editor.

Android

  • Improved Background service groundwork. Most of the structural changes required for an Android background service have been completed. The service itself, which would advance pet state and send notifications while the app is closed, remains in development.
  • Note Current limitation. Until the service ships, Android pets do not progress while the app is closed. The Android build is best suited to a dedicated device kept running in the foreground.

Arena (Planned, Not in This Beta)

  • Not in beta 1 Arena status. The Arena is not implemented in this release. The design is settled and server-side groundwork is in place, but the feature is not yet playable.
  • Planned Arena design. Seasons last one week. Each player uploads a team of three pets, which are removed from their device for the duration of the season. Each player receives a fixed number of attacks to use against other players' teams; wins increase the player's score. All attacks and defenses can be reviewed in game. The top three players at season end receive Coin rewards. Seasons may be free-for-all or thematic, for example restricted to stage 4 pets or to a single attribute.
Beta notes. The Arena is not yet implemented and the Android background service is still under development. Accounts created against the development environment are not valid on the production build. New account verification codes may be delivered to the spam folder.
Platforms. Version 1.0 is available on the same platforms as 0.9: Windows, Python Desktop, Android, GamePi, and Batocera. The shop and Arena require an internet connection; Free Mode operates fully offline. Some Batocera images lack Python and pygame; verify compatibility before purchasing hardware specifically to run Omnipet.
Version 0.9.9 — UI Overhaul and Android Release December 20, 2025
Download release
This release contains a complete rewrite of the user interface, large content additions, and the first Android port. The project was also renamed from Omnimon to Omnipet to reflect its broader scope beyond Digimon.

User Interface

  • New UI cache system. The rendering pipeline now caches UI components, reducing draw calls by approximately 80% (from over 600 blits per second to under 100).
  • New Multi-input support. All scenes now support mouse and touch input alongside keyboard and joystick.
  • New Scene color themes. Each scene uses a distinct color (Library yellow, Digidex green, Freezer cyan, Battle red) for visual orientation.
  • New Resolution-aware layouts. Higher resolutions display more information rather than simply scaling existing elements.
  • New Component system. The UI is now built from a reusable component library covering buttons, grids, panels, lists, selectors, and displays.
  • Improved Typography. A new font system provides multiple sizes and weights for improved readability.
  • Improved Visual feedback. Hover states, focus indicators, and selection highlighting are now consistent across the interface.

Module Content

  • New Vital Bracelet (VB). All 37 official DIM Cards are implemented with evolution lines, stats, and backgrounds.
  • New Vital Hero (VH). Complete collection of Vital Hero DIMs with their evolution mechanics and rosters.
  • New Vital Bracelet BE (VBE). The latest generation of Vital Bracelet content is included.
  • New Godzilla DMC. The Digimon × Godzilla crossover device is implemented with original sprites and attack animations.
  • New Original Digital Monster (DM). The 1997 device, recreated with color sprites and authentic gameplay.
  • New Digital Monster Ver. 20th (DM20). Anniversary edition with expanded rosters and updated mechanics.
  • New Pendulum series. Pendulum Version .0 and Version .5 are now supported, including shake mechanics.
  • Stats Content totals. 1,583 characters, 1,047 enemy types, 225 unlocks, and additional backgrounds and items were added in this release.
  • Improved VB ruleset. A new ruleset specific to Vital Bracelet mechanics covers step-based evolution, vital values, and VB battle protocols.

Library and Quests

  • New Library scene. A central hub for quest management with a vertical panel showing up to three active quests and their progress.
  • New Quest status indicators. Color-coded panels distinguish claimable, in-progress, not-started, and completed quests, with reward icons and completion markers.
  • New Quick navigation. Direct access to the Freezer Box, Digidex, and Settings from the Library hub.
  • Improved Reward popup. Quest reward claims now display an animated popup with the earned items and quantities.

Freezer Box

  • New Dual view. The Freezer Box now toggles between the Party view and a Box view containing ten boxes of twenty slots each (200 total pet capacity).
  • New Grid navigation. A 4×5 grid layout displays sprites, names, and states for each pet. Empty slots are clearly marked.
  • New Page navigation. Box pages can be changed with arrow buttons (mouse) or L/R shoulder buttons (controller). Navigating off the edge of a grid changes pages automatically.
  • New Context menus. Pet-specific options (Store/Add, Stats, Clear) are available based on the pet's state and the current view, with keyboard shortcuts.
  • Improved Stats panel. Pet statistics can be viewed directly from the Freezer for both party and stored pets, without changing scenes.

Digidex

  • New Dual view modes. The Digidex now supports a Grid view for compact browsing and a Tree view for evolution line visualization.
  • New Filtering. Multi-criteria filters cover Module, Stage, Discovery status, and Attribute. Filter selections persist between sessions.
  • New Evolution tree view. A hierarchical display shows complete evolution paths from Baby I through Ultra, including connecting lines and stage labels.
  • New Adaptive controls. The filter button is hidden in Tree view to maximize visualization area, and reappears in Grid view.
  • Improved Sprite caching. A sprite cache loads only visible entries on demand, supporting the 1,500+ character collection efficiently.
  • Improved Entry details. Entries now show sprite, name, module, stage, and discovery status with color-coded indicators.

HD Sprite Support

  • New Dual sprite directories. Modules may provide both classic sprites (monsters/) and high-definition sprites (monsters_hidef/) with automatic fallback.
  • New Module-level configuration. Each module specifies its preferred sprite type via the sprite_type setting.
  • New Vital Bracelet HD sprites. All VB, VH, and VBE modules use sprites extracted from official DIM Cards.
  • Improved Sprite scaling. Automatic scaling preserves visual quality and aspect ratio across resolutions.

Platform Support

  • New Android port. A full Android version is now available with touch-optimized controls and mobile-appropriate performance settings.
  • Improved GamePi. Continued refinement for the Raspberry Pi Zero 2W, including frame-rate and power efficiency improvements.
  • Compatibility Batocera. Batocera support is maintained. Some Batocera builds have limited pygame implementations and may not function correctly.

Performance

  • Improved Rendering pipeline. The rendering system was rewritten with component caching, reducing screen draws by 80–90% across all scenes.
  • Improved Hash function. Surface caching now uses Python's built-in id() rather than MD5, eliminating approximately 17 seconds of CPU time per profile.
  • Improved Shadow compositing. Pre-rendered shadow and sprite composites reduce four blits per shadow to one.
  • Improved Redraw detection. Components redraw only when their data changes.
  • Metrics Per-scene results. Status: 634 → 140 blits/s. Inventory: 473 → 60. Training: 510 → 30. Library: 812 → minimal.

Battle System

  • New View-based architecture. The battle scene is now organized around per-mode views (Adventure, Jogress, Armor, Versus, Protocol).
  • New Battle displays. Specialized UI components for Jogress (three-hexagon DNA visualization), Armor (single hexagon with preview), and Versus (dual hexagon matchup).
  • Improved Context-aware UI. Scene UI is hidden during battle encounters, leaving only the HP bar visible.
  • Fixed PvP HP bar. The right side of the HP bar no longer renders incorrectly in Versus mode.
  • Improved Component scaling. ArmorDisplay, JogressDisplay, and VersusDisplay now scale hexagons, borders, and sprites correctly across resolutions.

Training

  • New Training mode selection. A dedicated selection screen for Power, Speed, Vital Values, and Excite training with availability indicators per module.
  • Improved Pet display caching. Training scenes cache pet sprites using tuple comparison rather than set operations.
  • Fixed Frame drops. Frame drops during training animations were eliminated by optimizing draw_pets().

Inventory

  • New Tabbed interface. Items, Evolution Items, and Unlockables are separated into tabs.
  • New Visual item list. A scrollable list shows sprites, names, quantities, and descriptions with hover tooltips.
  • New Inline pet selector. A pet selector at the bottom of the inventory screen allows quick target selection when using items.
  • Improved Feeding modes. Mode indicators show All, In-Need, or Selection with clear visual feedback.

Bug Fixes

  • Fixed Invisible component caching. Components with visible=False now create a cached surface, preventing infinite redraw loops.
  • Fixed PetSelector redraws. The PetSelector no longer redraws unless its theme colors actually change.
  • Fixed QuestPanel redraws. Quest panels no longer redraw every frame.
  • Fixed Grid redraws. PartyGrid and FreezerGrid mark a redraw only when their items change.
  • Fixed Display component redraws. JogressDisplay, VersusDisplay, and ArmorDisplay now compare colors before marking a redraw.
  • Fixed TextPanel compatibility. Added ui_local parameter support for coordinate consistency across UI components.

Developer Tools

  • New Performance profiling. main_profile.py integrates cProfile for performance analysis.
  • Improved Debug logging. Component-level redraw tracking is now available for UI optimization work.
  • Improved Blit counter. A real-time blits-per-second counter is available for monitoring rendering load.
Migration from Omnimon. The project name has changed from Omnimon to Omnipet. Save files and module data remain compatible; existing users can extract the new version and continue with their progress intact.
Version 0.9.8 — PvP and Quest System August 30, 2025
Download release

Available Downloads

  • WindowsOmnipet_Windows_Ver_0.9.8.zip — Standard Windows distribution with all modules and the Module Editor.
  • ExperimentalOmnipet_Nuitka_Windows_Ver_0.9.8.zip — Nuitka-compiled Windows build. Faster but experimental; use if the standard build has performance issues.
  • PythonOmnipet_Python_Desktop_Ver_0.9.8.zip — Cross-platform Python build for Linux and macOS. Requires pip install pygame psutil.
  • BatoceraOmnipet_Batocera_Ver_0.9.8.zip — Place in /userdata/roms/pygame/. Input configuration may need adjustment.
  • GamePiOmnipet_GamePi_Ver_0.9.8.zip — For the Raspberry Pi Zero 2W. May be installed over an existing installation in home/Games/Omnipet, or used with the pre-made image for clean installs.
Installation notes. The Module Editor source is available on GitHub only; it is not included in the Batocera and GamePi releases due to Linux incompatibility. For clean GamePi installs, the pre-made image is recommended and WiFi can be configured via the Raspberry Pi Imager. The Python Desktop build requires pip install pygame psutil. There is no automatic update system in this release.

Major Features

  • New PvP battles between devices. Two Omnipet devices may now battle over WiFi. Both devices must have compatible modules installed.
  • New Daily quests. Each day the game selects three quests for the player. Quests are module-specific and are authored in the Module Editor.
  • New Random events. Events triggered by XAI rolls can drop items or initiate special encounters. Events are configurable in the Module Editor.
  • New Library menu. A new menu option tracks and claims quest rewards. The Digidex and Freezer Box have been moved here from the Settings menu.

Debug Tools

  • Improved Debug menu. Pressing F12 on the main screen now opens a multi-page debug menu exposing all pet attributes for testing and module development.
  • New Evolution path testing. The debug interface allows module developers to test evolution paths and adjust attributes at runtime.

Module Editor

  • New Random Events tab. Authors may define custom random events with item drops and special encounters.
  • New Daily Quests tab. Authors may define daily quests with custom objectives and rewards.
  • Improved Multiple eggs. No limits on the number of eggs or modules. A single version may be used for interconnected evolution lines, or separate versions for independent lines.

Hardware and Platform Support

  • Improved GamePi Zero 2W image. A complete plug-and-play image is available. The game loads as a service on startup.
  • Improved Input mapping. Custom controls can be configured via input_config.json. An input test application is included for mapping keyboard or joystick controls; a default joystick mapping is provided.
  • Technical Raspberry Pi Imager. WiFi may be configured when writing the GamePi image using the imager's advanced options.

Game Balance

  • Improved Battle damage. Attack damage now accounts for pet level and mini-game score, based on DMX attack patterns.
  • Improved Sickness probability. Sickness chances were rebalanced: a flat rate for wins, scaled rates for losses, with protein overdose and disturbance penalties capped at 50%.
  • Note Stage 1 lifespan. Stage 1 pets are intentionally short-lived (10 minutes) and do not sleep.

Bug Fixes

  • Fixed Egg selection scene. Various issues with the egg selection scene at different resolutions and with Digidex type/egg unlock functionality were resolved.
  • Fixed Battle failure handling. Battle failure and result processing have been corrected.
  • Improved Empty module handling. Empty module folders no longer cause crashes during loading.
Platform compatibility. Windows, Linux, and GamePi are fully supported. Batocera support is maintained. GarlicOS has limited pygame support. Knulli compatibility is under investigation.

Version 0.9.4 — Modularity and Tooling June 18, 2025

Major Features

  • NewDMX module completion. All unlockables are available and all items are functional, with custom icons and effects. Only special encounters remain to be implemented.
  • NewCustom module items. Modules may now define custom items with status_boost and status_change effects. The framework is extensible to additional effect types.
  • NewStandalone Windows build. A vpet.exe file allows running the game without a Python installation. This is an initial release; bugs are expected.
  • NewDynamic resolution and frame rate. Resolution and frame rate are configurable via config.json. The game supports 4K at 144 FPS on high-end systems.
  • NewNon-Pi Linux support. Compatibility checks have been added for standard Linux distributions beyond Raspberry Pi systems.

System Improvements

  • ImprovedScene optimization. All scenes have been optimized for low-power, low-CPU devices.
  • ImprovedPet modularity. Pets are now fully modular, with all options and checks configured in module JSON files. DMC pets may now have condition hearts.
  • ImprovedModular unlockables. Modules may define their own secret evolution lines, eggs, and backgrounds.
  • ImprovedBattle menu. Now displays proper icons for module adventure modes. Up/down keys can be used for area and round selection.
  • ImprovedHigh-resolution backgrounds. Enhanced backgrounds for resolutions above 1024×768, although some module backgrounds are still pending.

Version 0.9.4b Hotfix

  • FixedEgg hatch crash. A critical crash following egg hatching has been resolved.
  • NewMulti-pet support. The pet limit is configurable in config.json. Pet size adjusts relative to resolution and pet count for optimal display.

Development Tools

  • NewModule Editor progress. The visual module creation tool is approximately 70% complete. It covers module editing, backgrounds, items, pets, evolutions, sprites, and enemies.
  • NewD-3 module development. A custom D-3 module is in development, featuring Digimentals and Armor Digivolutions.

Platform and Technical
